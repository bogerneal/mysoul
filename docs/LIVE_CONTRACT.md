# CWA 真實資料解析與查詢

更新：2026-10-06。已在本機完成 CWA → 解析器 → SQLite → live 查詢。原始 JSON 結構以 2026-10-04 下午／晚間及 2026-10-06 凌晨三次授權擷取為依據，單位參考 [CWA 產品文件](https://opendata.cwa.gov.tw/opendatadoc/Forecast/F-D0047-001_093.pdf)。

## 已核對的資料契約

| 項目 | 處理 |
| --- | --- |
| 外層識別 | `result.resource_id=F-D0047-091`、`records.Locations[0].Dataid=D0047-091` |
| 地區 | 22 個縣市；Geocode／名稱對照取自真實回應，見套件中的 `cwa_counties_v1.json` |
| 元素 | 僅解析 `最低溫度`／`最高溫度`，值分別為 `MinTemperature`／`MaxTemperature`；其他因子忽略 |
| 單位 | 攝氏度；回應本身無獨立單位欄位，依上述資料集與官方欄位定義解讀 |
| 時間 | 含時區 ISO 格式；內部 UTC，摘要顯示台灣時間 UTC+08:00 |
| 時段 | 下午實測 14 筆、晚間實測 15 筆；第一筆可不足 12 小時，其後連續 12 小時；末端為台灣時間 06:00 |
| 完整性 | 所有縣市的時段集合一致，最高／最低溫依起訖配對；缺縣市、重複、缺段、間隙或重疊拒絕入庫 |
| 發布時間 | API 回應未找到已驗證的發布時間，保留 `None` 與 `missing_source_issued_at`，不推算 |
| 缺值 | 本次最高／最低溫樣本均有值。null、`-`、`-99` 等尚未確認為溫度缺值語意，先拒絕整批並保留舊資料；不沿用降雨機率的 `-` 規則 |

14／15 筆與末端時間是兩份樣本驗證後的版本化防錯條件，不是宣稱 API 永不改變。若日後 CWA 合法格式改變，先取得樣本核對再調整，避免靜默接受截斷資料。

## 真實更新與查詢

```powershell
uv run --locked weather-data update-live --prompt-key
uv run --locked weather-data status --mode live --summary --location 臺北市
```

輸入授權碼時不顯示字元，也不保存 Key。若已有程序環境變數 `CWA_API_KEY`，可省略 `--prompt-key`。更新取得全部縣市；查詢不再呼叫網路，可用縣市名稱、台／臺別名或代碼篩選。省略 `--summary` 可取得 JSON。

更新全程在程序更新鎖內，成功才原子切換快照。HTTP、解析、覆蓋或 SQL 失敗均保留舊資料並記錄失敗。已過期或異常遠期的網路回應不得更新成功時間；即使擷取時间較新，也拒絕覆蓋範圍退回較早末端的 live 預報。這只能部分防止倒退，同一覆蓋期間的來源修訂先後因缺少發布時間仍無法完全判定。

## 匯入已擷取樣本

```powershell
uv run --locked weather-data import-cwa --file data/private/cwa-20261004T071909450480Z.json --fetched-at 2026-10-04T07:19:09.450480Z
```

`--fetched-at` 必須提供原始擷取時間與時區，不可填現在的時間。匯入不會發送請求；過期歷史樣本仍可供查驗，但不會因今天重匯就變成最新。若目前 live 快照已比這份樣本新，會拒絕倒退；可用 `--db data/archive-test.sqlite3` 匯入獨立測試資料庫。
