# 參考分析與設計決策

本文件記錄本次規畫的證據與假設，供實作時追蹤。實際功能尚未開發。

## 1. 使用者指定網站

來源：[台灣即時氣象地圖](https://taiwan-weather-map.vercel.app/)。

本次取得公開頁面的 HTML，確認標題為「台灣即時氣象地圖」，初始介面包含以下控制項：

- 氣溫、雨量、雷達、颱風、風速風向、濕度、天氣及測站點位。
- 縣市界線、氣溫數字標籤、深色／街道圖底圖與「定位我的位置」。
- 攝氏溫度色階圖例，以及取得中央氣象署即時資料的載入提示。

HTML 顯示全螢幕地圖容器與桌面側邊控制面板，並含 Next.js 靜態資源。這只能證實可見控制項與前端線索；本次未在瀏覽器中操作地圖，未驗證各圖層、定位、手機版、API 正確性或後端架構，也不據此推定其資料庫與部署設計。

採用其「地圖為主要視圖、圖層與圖例清楚呈現、資料載入有狀態」的互動概念。MVP 不複製全部圖層，也不將即時觀測介面中的讀值當成未來預報。

## 2. 使用者提供的課程圖片

圖片主題為「AI 創新微課程 Taiwan Weather Forecast」，24 個步驟涵蓋：

| 課程步驟 | 工程工作 | 對應階段 |
| --- | --- | --- |
| 1–3：課程、生活應用、CWA 平台 | 確定使用者、資料來源、MVP 範圍 | M0 |
| 4–7：API、JSON、最高最低溫、整理 | 資料契約、驗證與解析器 | M1 |
| 8–10：SQLite、資料表、SQL 驗證 | schema、migration、冪等寫入 | M2 |
| 11–16：Streamlit、查詢、圖表、表格 | 同一查詢模型驅動所有視圖 | M3 |
| 17–19：地圖、日期、成果展示 | 地理對照、代表點、地圖互動 | M4 |
| 20–21：品質與 GitHub | 自動測試、CI、文件、版本管理 | 全程／M5 |
| 22–24：延伸、回顧、探索 | 通知、其他資料源、AI 摘要 | P2 |

圖片中的日期、數值、JSON 欄位與 SQL 為教學示例。本專案不直接使用它們作為真實氣象資料。圖片使用的北部／中部等地區分組也不直接作為 CWA 縣市識別碼；若未來新增區域彙整，必須先定義縣市對照與彙整方法。

圖片只存在於對話附件，本次未將圖檔收錄進儲存庫；亦未重製其中人物、標誌或版面素材。

## 3. 初期決策

| 編號 | 決策 | 理由與重新評估條件 |
| --- | --- | --- |
| D01 | 先做縣市一週預報 | 對應課程資料流，限制第一版範圍；實際縣市涵蓋由 M1 驗證 |

| D03 | 地圖以縣市代表點呈現 | 避免將縣市預報畫成未經驗證的連續溫度場；地理來源與授權在 M4 確認 |
| D04 | 先保留 API 時段，再衍生日摘要 | 避免用日期欄位丟失日夜與跨日資訊 |
| D05 | 真實、示範、過期資料明確區隔 | 更新失敗時不以示範數字冒充真實預報 |
| D06 | 不因參考站位於 Vercel 就指定相同部署 | 部署需配合 Python 服務與 SQLite 持久性；進階 Web 前端另立決策 |

本次未提供 CWA API Key、未選定正式部署環境、未確定底圖及縣市地理資料供應者。這些事項不阻礙規畫與離線解析器開發；真實資料驗收與正式發布前必須解決。
